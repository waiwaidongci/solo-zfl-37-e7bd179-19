# 墨锭试磨室

运行：

```bash
npm start
```

访问 `http://localhost:3037`。数据保存在 `data/ink-stick-testing.json`。

## 数据恢复台

主页右上角进入「数据恢复台」（`/recovery`），为全部墨锭、试磨记录、日志和统计提供恢复点：

- **全量 / 增量恢复点**：首个恢复点为全量；之后默认为增量，只记录相对上一点的改/增/删。增量通过 `prevDigest` 链接摘要与父点形成哈希链，沿链可还原全部数据。
- **校验**：每个点都带内容摘要（SHA-256，规范化 JSON）和点摘要。任一点摘要不符、父点缺失或链接摘要不符（断链），该点及其下游都标记为不可用，**预览和恢复一律拒绝**。
- **预览**：恢复前显示将「新增 / 修改 / 丢失」的墨锭数量及明细，并给出目标版本与当前版本的墨锭、日志、试磨总数。
- **恢复**：确认后执行。恢复期间所有业务写入返回 `409 restore_in_progress`，新写入不会混入被回滚版本；恢复采用「备份 → 替换 → 记录完成」的崩溃安全流程，失败或中断（含进程重启）都会自动回到恢复前状态。客户端生成请求 ID，重复/并发的同一请求只执行一次（幂等）。
  - **回滚也失败时不丢数据**：若恢复失败、且自动回滚的落盘也失败（如磁盘故障），日志标记为 `rollback_failed`（绝不误报已回滚）并**保留备份**；重启会再次尝试回滚。磁盘恢复后可在恢复台点击「重试回滚找回数据」，或调用 `POST /api/recovery/restore/:id/recover-rollback` 把恢复前数据写回，成功后才删除备份。
  - **待找回期间写保护**：一旦进入待找回（`rollback_failed`）状态，**建档、状态变更、日志、试磨等全部业务写入以及恢复点改动都会被拒绝**（`409 rollback_in_progress`），避免覆盖可找回的恢复前数据；读取与恢复台（查看、校验、预览、重试回滚）照常可用。只有重试回滚成功（或重启后自动回滚成功）后才恢复写入。
- **保留策略**：按数量保留，最旧优先清理。被**钉住**的恢复点不会被清理；链上仍被增量依赖的点不会被破坏（自动清理只删链尾或整体淘汰最旧的全量子树）。损坏点不参与自动清理。
- 页面为响应式布局，桌面与手机均可操作（窄屏下恢复点列表转卡片，按钮与状态始终在屏内，无横向溢出）。

恢复点与日志存于 `data/recovery/`（`points/`、`journals/`、`pins.json`、`config.json`）。

## 验证

```bash
npm test
```

`npm test`（`node --test --test-concurrency=1`，串行执行保证确定性收尾）不依赖全局安装，项目路径含空格/中文等需要 URL 编码的字符时也可直接跑通（测试以解码后的真实路径启动服务）。可连续多次重复运行：
- 子进程收尾统一走 `killChild`/`waitExit`：**等待 `exit` 前先判断进程是否已退出**，避免“退出通知早于监听注册、之后空等一个不会再来的事件”导致取消/挂起；先 `SIGTERM`，超时升级 `SIGKILL`；
- 无头浏览器显式关闭，临时数据目录随用例结束清理；就绪失败也先杀子进程。

因此重复运行不会出现取消、挂起或残留进程，结果可对照 `STABILITY.md`。

覆盖：并发写入不丢数据且建点期间可继续写、摘要损坏阻断、链条断裂阻断、重复/并发恢复幂等、恢复失败回滚、恢复中崩溃重启回滚、**回滚写失败时保留备份并可重试找回（运行时与重启两条路径）**、**待找回期间四类业务写入全部被拒、重试成功后放行**、保留策略/钉住/依赖保护、预览数量、恢复期间写入失败、**含空格路径启动、手机窄屏无横向溢出（无头浏览器实测 320/360px）**。

> 窄屏布局测试在检测到 `playwright-core` 与可用的无头浏览器时运行；二者缺失时自动跳过，不影响其余测试。
